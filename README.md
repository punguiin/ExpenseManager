# ExpenseManager

Застосунок для обліку гаманців та транзакцій.

## Структура рішення

Рішення складається з 4 проєктів, розділених за принципами багатошарової архітектури та Single Responsibility:

### ExpenseManager.Storage (бібліотека класів)
Містить класи, які відповідають за зберігання даних. Ці класи не містять обчислюваних полів, колекцій дочірніх сутностей чи посилань на батьківські сутності.

- **WalletEntity** — клас для зберігання даних гаманця (Id, Name, Currency). Id не має сетера, оскільки він не може змінюватися після створення.
- **TransactionEntity** — клас для зберігання даних транзакції (Id, WalletId, Amount, Category, Description, Date). Id та WalletId не мають сетерів.
- **Currency** — перечислення валют гаманця (UAH, USD, EUR, GBP, PLN).
- **TransactionCategory** — перечислення категорій транзакцій (Groceries, Cafe, Transport, Auto, Salary, Utilities, Entertainment, Health, Clothing, Other).

### ExpenseManager.Models (бібліотека класів)
Містить класи, які відповідають за відображення, створення та редагування сутностей. На відміну від класів зберігання, ці класи можуть містити обчислювані поля та колекції.

- **WalletModel** — модель гаманця для відображення. Містить список транзакцій (`List<TransactionModel>`) та обчислюване поле `TotalBalance` (сума всіх транзакцій).
- **TransactionModel** — модель транзакції для відображення. Містить обчислюване поле `IsExpense` (true, якщо Amount < 0).

### ExpenseManager.Services (бібліотека класів)
Містить сервіс для роботи зі сховищем та штучне сховище з початковими даними.

- **ExampleDataStorage** — внутрішній статичний клас (`internal static`), доступний лише для ExpenseService. Містить початкові дані: 3 гаманці з різними валютами та 12 транзакцій (10 для першого гаманця, 2 для другого).
- **ExpenseService** — публічний клас, який є єдиною точкою доступу до даних. Відповідає за отримання даних зі сховища та перетворення об'єктів зберігання (Entity) в об'єкти відображення (Model).

### ExpenseManager.Console (консольний застосунок)
Точка входу в програму. Забезпечує взаємодію з користувачем через консольне меню.

## Залежності між проєктами

```
ExpenseManager.Console
    └── ExpenseManager.Services
    │       ├── ExpenseManager.Storage
    │       └── ExpenseManager.Models
    └── ExpenseManager.Models
            └── ExpenseManager.Storage
```

## Потік роботи застосунку

1. Після запуску відображається список всіх гаманців.
2. Користувач обирає гаманець за номером — відображається детальна інформація (валюта, баланс) та список транзакцій.
3. Користувач обирає транзакцію за номером — відображаються повні деталі (сума, категорія, опис, дата, тип).
4. З будь-якого екрану можна повернутись назад (b) або вийти з програми (0).

## Сутності

### Гаманець (перший рівень)
- Унікальний ідентифікатор
- Назва (наприклад, "Готівка", "Картка")
- Валюта (enum Currency)
- Загальна сума (обчислюване поле — лише в Model)

### Транзакція (другий рівень)
- Унікальний ідентифікатор
- Ідентифікатор гаманця
- Сума (додатна — дохід, від'ємна — витрата)
- Категорія (enum TransactionCategory)
- Опис
- Дата
- Чи є витратою (обчислюване поле — лише в Model)
